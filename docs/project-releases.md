# 项目产品分支发布管理详细设计

本文记录发布管理的当前契约。统一初始迁移包含发布管理及可选发布名称，运行基线为版本 1、48 张业务表。DDL 位于 [schema.sql](schema.sql) 末尾。现有产品分支、分支和仓库范围规则见 [产品分支设计](project-variants.md)，凭证边界见 [服务集成设计](service-integrations.md)。

**交付状态。** 产品分支详情的「发布管理」已实现发布草稿、按类型备料、修订历史、仓库范围预览和基线、MR 选取与合并、补录提交、回退 MR 创建或关联、冻结送验、退回与归档、按清单导出 ZIP。远端写入使用该连接上操作者本人的首选凭证；服务端先写操作意图，逐步执行并保留核实结果。系统设置的「临时文件」提供来源预览和手动清理。在线配置限 1 MiB，其他单文件限 100 MiB。实库、受控 GitLab 与浏览器验证边界见[开发说明](development.md)。

## 1. 发布对象与权限

一份发布属于一个项目的一个产品分支，包含可选名称、版本号、Markdown 说明、所选 MR、全部范围仓库的产品分支主干 SHA，以及四类可选材料。环境及其分支不参与快照。同一份发布可容纳多个大需求，以一个版本一起验收。允许零 MR 的纯材料发布，所有范围仓库仍记录 SHA 并打新 Tag。空范围可以先保存草稿；当前实现要求开始发布时即至少有一个范围仓库，且全部基线可用，送验与归档继续校验完整范围。创建与阶段面板提前说明此条件，仓库关联由系统管理员在控制台维护，产品分支范围与主干由有管理权限的用户配置，不因前端指引放宽后端权限。

发布名称面向阅读和识别：前后 Unicode 空白去除后最多 120 个 Unicode 字符，必须为单行，拒绝内部控制字符及行/段落分隔符。全空白按空名称保存。所有入口统一优先显示名称，未填写时动态回退版本号；数据库不复制版本号作为名称，修改草稿版本时默认显示随之更新。名称可以重复，不参与版本或 Tag 的唯一性，不影响远端 Tag、URL 和发布 ID。版本号及 Tag 在名称下作为次级信息，回退时避免重复展示同一版本。

| 操作 | 有效项目成员（含团队继承） | 项目管理员 |
| --- | --- | --- |
| 查看历史、下载有权访问项目的清单和文件 | 可 | 可 |
| 编辑协作中的说明、选取 MR、增删改材料、调整 SQL 顺序 | 可，记录操作者 | 可 |
| 建发布、改版本号、设 Tag 前缀、确认范围和基线 | — | 可 |
| 修改发布名称 | — | 草稿及合并与备料阶段可；待验收及后续阶段只读，退回修改后可再编辑 |
| 开始合并、处理清单外变更、创建或关联回退、送验 | — | 可 |
| 验收、退回、终止、归档、核实或补做远端操作 | — | 可，可与先前合并人相同 |
| 系统临时文件预览与清理 | 仅系统管理员可操作 | 仅系统管理员可操作 |

发布管理沿用项目管理授权中系统管理员的独立管理资格，远端操作同样要求其本人凭证。团队管理员在项目内按有效项目角色判定。每次写入核对当前账号、成员来源、项目与产品分支状态。归档项目/产品分支允许按现有读权限查阅历史。项目或产品分支有占用中的发布时阻止归档，草稿随父对象归档只读，可在父对象恢复后继续；已有发布历史的产品分支禁止硬删除。仓库解绑保留历史名称和身份，执行阶段占用的仓库、主干绑定及连接实例不能被改绑或删除。

项目管理员设置稳定的产品分支 Tag 前缀，版本号由管理员填写。当前版本固定拼接规则 `{产品分支Tag前缀}{版本号}`，例如 `acme-v1.4.0`、`acme-v20261103`。工程约定：未设置前缀时先设置再创建发布，前缀可用项目与产品分支编码区分共享仓库，最长 96 个 ASCII 字符；版本号最长 96，首尾字母或数字，中间可含点、下划线、连字符，可填写日期追加序号。两者不含斜杠，服务端按 Git ref 规则复核拼接结果。创建时保存完整 Tag 和采用的前缀，变更前缀仅影响此后新建的发布。草稿改版本号仍用其保存的前缀。从开始合并起固定版本号。归档及终止记录继续占用产品分支内版本号。远端冲突必须按实际仓库检查。

## 2. 状态与冻结边界

| 状态 | 允许操作与迁移 |
| --- | --- |
| draft 草稿 | 可并行创建，成员协作，管理员刷新范围与基线。开始合并或无 MR 发布进入 integrating；也可终止。 |
| integrating 合并与备料 | 已占用产品分支及范围内全部仓库主干。允许补材料，管理员确认后追加 MR、处置额外提交、核实已发出的操作。核对完成后冻结送验，进入 reviewing。 |
| reviewing 验收 | 冻结版本只读，可整包或单文件下载。管理员通过后进入 accepted，退回须写原因并返回 integrating。再次送验生成新清单，前一版保留。 |
| accepted 待归档 | 管理员对已通过清单启动打 Tag，进入 tagging。在首次打 Tag 前需要修改时，可撤销本次通过并退回，保留原结论和撤销审计。 |
| tagging 归档中 | 逐仓核实和补做，所有目标 Tag 均指向冻结 SHA 后进入 archived。部分成功、权限失败、远端结果未知都留在此状态。 |
| archived 已归档 / terminated 已终止 | 终态只读，可按历史清单取回文件。终止记录原因、已合入/已回退的事实及已有远端 Tag。 |

同一产品分支从进入 integrating 到归档或终止始终占用一个活动名额，验收退回继续持有。跨产品分支、跨项目按**远端仓库和具体主干**互斥，包含本次零 MR 的仓库。同一仓库不同主干可并行。锁仅约束 AntCDP 发起的发布，GitLab 外部写入通过差异核对发现。

开始操作前预览全量范围与差异。事务内锁项目、产品分支、发布，复核 scope_token、ETag 和基线，再按远端键排序，一次取得全部占用或整笔回滚。remote_key 为带版本、长度前缀的「GitLab 实例规范地址（含子路径）、平台 repo_id、精确分支字节」的 SHA-256；不能用项目仓库关联 ID 代替。对同一实例使用统一规范地址；当前按规范地址识别实例，无法自动识别不同域名指向同一实例；部署应使用统一地址，重复入口需先消歧再启用发布。冲突只返回操作者有权限查看的持有方。并行准备不意味着自动排队外发，管理员解决冲突后再次确认。

终止活动发布前停止新操作，先核实已发送且结果未知的请求；查询不到目标不能直接认定请求未生效。遇到无法证实结果的长时间阻塞，保持占用，由管理员恢复 GitLab 可读性并核实，列出残留提交和 Tag，由管理员确认处置后事务释放全部占用。终止不会自动回退提交或删除任何 Tag。首次打 Tag 后材料和冻结版本固定，只允许补齐或登记残留并终止。归档最终事务复核清单、各仓结果及权限，把 ended_at、状态、审计及占用释放一并提交。

## 3. 主干基线、合并与差异核对

1. **建草稿。** 从产品分支动态范围全量求值，记录仓库关联 ID、平台 repo_id、实例身份、路径及主干名。草稿刷新须显示增减清单并由管理员确认。已移出仓库的材料需改归属或移出清单；历史修订继续可读。预览按远端身份和分支检查重复映射。若两个项目仓库条目指向同一目标，列出两条路径，请管理员消除重复后重新确认。进入合并时固定范围，之后产品 Git 分支规则变化只影响后续发布。
2. **确定基线。** 同一产品分支、同一远端仓库和主干优先使用上次成功归档 SHA。首次加入时采集当时的主干 SHA、采集时间与来源；读取失败标记待采集（baseline_sha 与 baseline_at 为空，禁止开始合并），管理员显式重采，展示实际采集时点。首次可逐仓选择自定义 Tag 或完整 SHA，解析为固定 SHA，验证它是当前主干祖先并留审计。默认基线以前的代码视为起始存量。等待中的草稿在开始前若已有更新的归档版本，重算预览并要求重新确认。若前一份是首次发布且已终止，下一份对相同远端主干沿用前次实际开始合并时的基线，并核对残留变更；不得以终止后的主干 SHA 跳过未归档的提交。
3. **合并。** 成员从本产品分支仓库选 MR，按仓库和 IID 唯一。管理员核对目标主干、源 HEAD、审批、冲突和流水线状态；发起合并传入已确认源 SHA，源变化需重新审阅。遵守 GitLab 当前保护规则。已在外部合并的 MR 核实后可纳入。同仓多个 MR 明确顺序逐条执行，任一步阻塞则保留已成功项。待合并或已受理均须读回最终合并状态和结果提交。
4. **核对差异。** 每仓以固定基线和候选主干两个 SHA 比较。分页枚举可达新增提交，通过 MR、merge/squash 结果及祖先关系解释其归属，避免把源分支提交重复列为额外变更。直接提交、外部合并等无法归属部分须补录 SHA、说明和确认人，或关联回退。历史分叉、比较超时或结果被截断时阻止送验，显示未核实范围，须补齐证据，不以空结果视为无差异。
5. **撤回。** 保留原 MR/提交记录，可关联 GitLab 已有的回退 MR，也可由管理员在 AntCDP 发起创建。后者从确认的主干 SHA 建专用分支、在该分支产生回退提交、再建目标为产品分支主干的 MR，每步均可单独核实。回退冲突留给人员修正并关联 MR。直到回退 MR 合并、结果进入候选主干，管理员确认修正内容及配套材料去留，才记为已回退。一个回退 MR 可撤回多个原项。每个原项以 reverted_by_change_id 指向同发布、同仓库的回退 MR；此前失败或更换的关联保存在操作记录和审计中。原项和回退项均列入冻结清单。
6. **冻结。** 对每仓记录实际读到的完整 SHA 和采集时间，重读主干，若相对差异预览已移动则重新核对。多仓快照指一组明确提交，各仓采集时间可能不同。提交冻结事务时验证本地发布版本未变、远端操作已结算及材料无冲突。此后外部推进主干不改变该清单，归档始终以其 SHA 建 Tag。

GitLab 操作只解析当前操作者在目标连接内启用的个人凭证（首选或显式选择本人凭证）。取当前 GitLab 用户身份以便操作记录对应到远端账号；个人凭证必须代表本人的 GitLab 身份。成员浏览远端 MR 同样只用本人凭证，无凭证仍可查看发布已保存的数据。禁止回退到系统、项目或他人令牌。出站复用连接的地址、TLS、限流与脱敏策略。方案对应 [GitLab MR API](https://docs.gitlab.com/api/merge_requests/)、[提交与回退 API](https://docs.gitlab.com/api/commits/)、[仓库比较 API](https://docs.gitlab.com/api/repositories/) 和 [Tags API](https://docs.gitlab.com/api/tags/)。

## 4. 材料与修订

| 类别 | 内容与校验 | 导出语义 |
| --- | --- | --- |
| sql | 直接上传脚本，文件名、可选仓库、目标数据库名、独立 Markdown。数据库名可先留空，由发布说明约定执行上下文。 | 单独排序，输出有序清单，排序写入冻结清单。 |
| object | 上传原件，目标对象路径必填，Bucket 与仓库可选，独立 Markdown。 | 目标对象键按原值记录，源文件名和目标路径分别展示。 |
| config | 在线编辑完整文件或能独立解析的增量，必填目标相对路径，单个文件名合法。可选仓库，独立 Markdown。 | 每项均单独保留、单独下载，交付侧程序合并。 |
| attachment | 任意文件，可多份，保留原始文件名。 | 分条下载，重名不覆盖。 |

发布说明和各条目 Markdown 均随清单冻结。大文件只在 Markdown 贴链接，平台原样随说明交付，由执行人员访问。在线配置原文最多 1 MiB；其他单个文件最多 104857600 字节，按实际读取字节数执行，不设单次发布文件总量上限。客户端一次请求上传一个文件，不要求分块或续传。四类均可为零。人工执行结果以管理员对冻结清单的验收时间、结论与说明记录，跨类别操作次序由发布说明表达。

配置支持 yaml、toml、json、ini、properties。以关联仓库（可空）和精确目标相对路径区分目标。统一用 `/`，拒绝绝对路径、盘符、反斜杠、空段、控制字符、单点和双点路径段。文件名取最终路径段。同一目标采用一种格式。编辑器高亮、标出错误行列，后端使用相同格式契约独立校验。增量有完整键层级，如 YAML 的 server → http → timeout，或 INI 中 section/key；语法校验无法推断漏写的父键，页面展示解析后的键路径供复核。

比较键路径时使用分段数组：JSON/YAML 对象按层级，TOML 按解析后的表与键，INI 按节和键，properties 按解码后的完整属性键（字面点不擅自拆层）。仅处理可确定的映射、标量、数组；重复键、格式不支持的扩展或无法唯一解释的结构报字段错误。增量根须为键集合，数组整体替换，保留原文，不执行变量替换；省略键表示保留，null 仅在支持该值的格式中表示值，不触发删除。同一目标同键不同类型或不同值、祖先标量/数组与子键同时出现均为冲突。相同值允许重复，完整文件与同目标其他条目同时出现应先整理为一个完整文件或多份兼容增量。草稿显示冲突双方，阻止送验。服务端按文件及目标分组流式处理，超出解析资源边界须给出明确原因。

**item-id 表示材料，revision-id 表示一次已保存修订。** 替换文件、改说明、改数据库名、Bucket、目标路径或仓库归属均新增修订，历史不覆写。只调整 SQL 顺序时更新发布中的顺序。移出材料只修改该条目在当前发布清单中的可见性。仅改元数据时新修订可继续引用同一 file_id，字节内容不另存；不在项目间做全局去重。每个修订、文件引用和冻结项必须属于同一发布、同一材料。历史下载针对具体修订重新鉴权。

材料编辑遇到 412 或提交结果未知时保留当前文字与所选文件，暂停保存和移出操作。用户显式读取最新材料清单及编辑版本，对照草稿、已保存元数据和配置原文，核对后才能采用新 ETag 继续编辑或移出；读取、核对均不自动重新提交。也可采用已保存修订并关闭；新增材料先按同名或同目标检查已有记录，不能把读取结果为空直接当作上次写入失败。材料已移出、当前发布或父对象只读时禁止覆盖，保留复制文字草稿和已保存修订下载入口；仓库已移出范围时必须重新选择归属。

## 5. 存储、打包与手动清理

```text
/app/data/
  tmp/uploads/releases/<upload-id>/payload.part
  releases/<project-id>/<variant-id>/<release-id>/
    sql/<item-id>/<origin-revision-id>/payload
    objects/<item-id>/<origin-revision-id>/payload
    configs/<item-id>/<origin-revision-id>/payload
    attachments/<item-id>/<origin-revision-id>/payload
```

origin-revision-id 是首次写入这份字节内容的修订，后续元数据修订可引用它。数据库存相对 storage_key、SHA-256 和字节数。路径段只用服务端生成的 ID 或固定分类。原始文件名、Markdown 链接、仓库路径、Tag、数据库名和对象键均不参与本地寻址。文件放私有卷，禁止跟随符号链接逃逸，下载通过鉴权接口，备份应同时保存数据库与匹配的数据卷。

**写入与崩溃恢复。** 使用同一卷暂存，持有上传/绑定占用，流式计数和计算摘要；关闭并持久化完成后，登记 staged 文件及预留的材料/修订 ID，再原子移至最终候选路径。事务核对归属和编辑版本，插入修订、切换当前指针、将文件标记 bound 后才算保存成功。新材料在绑定前不可见。事务失败留下 staged 记录；落盘前中断留下临时路径。重试先按上传 ID / 文件 ID 核实既有结果，数据库已绑定的文件永不列入清理。已移到最终路径但未绑定的文件，只有能核实 staged 记录且无修订引用时才允许人工清理。发现正式文件缺失或损坏应报完整性错误，保留记录用于从备份恢复。

**统一维护入口。** 各模块注册来源、允许根目录、候选识别及占用检查，发布是首个来源。系统管理员按来源预览候选 ID、数量、大小和原因；预览请求支持 offset 与 page_size（默认 100，范围 1–100），响应返回实际 offset、total、size_bytes 和 items，超出末页时回到有效末页。界面使用统一分页导航，改变页码或每页数量会清空本页选择。确认后按同一批候选逐项复核。清理与上传/绑定共用互斥，运行中、已被绑定、已变化或未知归属均跳过。单实例重启后核实暂存状态方可列为中断。客户端不能传任意文件系统路径。结果区分已清理、已不存在、跳过和失败，写入审计。无后台定期清理，成功保存的所有修订长期保留，包括被移出、被替换及终止发布的材料。既有头像等模块需要各自适配候选规则后才能接入。

**导出。** 冻结清单按不可变修订定位字节。授权后可下载任一文件或整包，ZIP 采用流式输出，按需使用 ZIP64。每项用独立条目目录，归档名只保留安全文件名，原始文件名与交付目标保存在清单中；统一处理重名、保留设备名和路径穿越。导出开始前检查所有引用可读，读取时核对摘要；遇到损坏中断传输，不能把残缺包报告为成功。清单格式有版本，排序稳定，验收与归档指向同一清单摘要。

```text
README.md                             # 发布说明、分类清单、独立说明和跨类别步骤
manifest.json                         # 版本、仓库主干 SHA、MR、修订、目标、顺序、摘要
sql/001-<item-id>/schema.sql
objects/<item-id>/logo.svg
configs/<item-id>/application.yaml
attachments/<item-id>/验收用例.pdf
```

## 6. 表职责与并发协议

[DDL 阅读副本](schema.sql)包含发布十表、产品分支 Tag 前缀及发布名称字段。所有 ID 的 API 表示为字符串。逻辑引用、状态、枚举及跨表归属由应用事务保证，沿用 MySQL 8 / InnoDB、UTC 毫秒时间。project_variant.release_tag_prefix 默认为 NULL，启用发布时设置。project_release.name 默认为空串，展示时回退版本号；改名不改变已冻结清单。启动时校验基线版本 1 与名称列类型、长度、字符集及非空默认值。

| 表 | 事实与约束 |
| --- | --- |
| project_release | 发布归属、可选名称 name、版本号、Tag、说明、当前清单、状态及写版本。name 为 utf8mb4 VARCHAR(120)，非空默认空串，不设唯一索引。variant_snapshot 保存创建时项目/产品分支名称、编码、Tag 前缀；活动状态 active_slot=1，其余为 NULL，唯一键在数据库内串行化。actor_user_id 为创建人。 |
| project_release_repository | 每次发布每个项目仓库一行，保存基线来源、观测时间与身份。移出设置 in_scope=false。remote_key 为远端仓库主干身份，活动范围内 active_remote_key=remote_key，其余为 NULL；跨发布唯一。 |
| project_release_change | 按仓库去重 MR IID 或直接提交 SHA，disposition 标识 selected/included/revert_pending/reverted/removed。evidence 白名单含标题、源/目标分支、源 HEAD、合并提交、相关提交证据及回退关联。 |
| project_release_item | 草稿当前材料，保存类型、当前修订指针、SQL 顺序和移出时间。排序在锁住发布后校验活动 SQL 完整排列。 |
| project_release_revision | 不可变，序号在材料内唯一。关联文件、各类目标字段、说明和创建人构成该次修订；无关类型字段为空。config_mode 为 full 或 delta。 |
| project_release_file | 保存一个物理原件，stable storage_key 唯一。状态 staged 或 bound，清理只处理无引用暂存；按来源修订生成路径。 |
| project_release_manifest | 每次送验一行。header 保存冻结的发布名称、版本、说明、项目/产品分支名称、Tag 和导出格式。digest 覆盖规范化头、排序后的全部项、修订内容标识和文件摘要。一次验收写一次 decision、reviewer、时间和说明。撤销通过另记审计，不覆盖原结论。 |
| project_release_manifest_entry | 每个仓库、变更和材料独立成行。repository 项固化路径、基线/最终 SHA 和时间，change 项固化归属与处置证据，item 项指向不可变 revision_id 并冻结顺序。按行写入/导出，避免整份清单受单个 JSON 字段大小限制。 |
| project_release_operation | 一次远端写命令，关联清单（归档必填）、调用人及请求摘要。同发布同人同 key 重放返回原操作；不同载荷返回冲突。执行或待核实期间占一个活动槽。 |
| project_release_operation_step | 每个远端副作用一步，依序记录意图、开始、结果、租约和核实证据；intent 含目标、已确认 SHA、凭证标识/版本及远端身份，observed 仅含受控字段。记录不含令牌、响应正文。 |

HTTP 写入使用强 ETag/If-Match 防止旧草稿覆盖。材料可使用条目 ETag 做细粒度编辑，但须锁父发布检查仍可写；任何影响冻结内容的成功修改均递增父发布版本。发布详情、清单、操作各按项目验证嵌套资源归属。一次送验在同一事务内校验全部状态、插入清单及全部明细、更新当前指针、写审计。审阅须指定 manifest_id 和 digest，避免对旧版误点通过。验收、撤销和终止的审计与状态变更同事务。项目仓库改名或产品分支改名不会改写过去清单。

名称修改同样递增发布写版本并使旧核对结果失效。创建及更新审计记录发布名称与版本号。退回后的改名只影响新的送验清单；历史清单和 ZIP README 标题始终使用该次冻结名称，旧清单缺少 name 或其值为空时回退该次冻结版本号，不读取当前发布名称替换历史内容。

冻结项采用固定版本的字段白名单。repository 项至少包含 connection_id、repo_id、repository_path、branch_name、baseline_kind（archived/initial/custom/carried，carried 表示承接未归档发布的基线）、baseline_sha、commit_sha 和 observed_at。change 项保存仓库项 ID、MR IID 或 SHA、处置、来源和核实结果。item 项保存 kind、revision_id、file_id、filename、size_bytes、sha256、可选仓库项 ID、类型专属目标及说明。清单摘要按 UTF-8 规范化 JSON、固定类别和条目顺序逐行计算，长度前缀区分记录边界。digest 本身、验收结论和后续打 Tag 结果不参与该摘要。

**远端操作恢复。** 本地先落操作和每步意图，提交后才外发；不持 MySQL 事务等待网络。调用前再次验证操作者权限、个人凭证和连接状态，写步骤租约与尝试标识。步骤状态 pending → running → succeeded/failed/unknown，可标记为未开始。重放先验证当前访问权，再按调用人和幂等键查找记录并比对请求摘要；相同请求即使携带原 ETag 也返回已有操作，只有首次外发需要用当前写版本校验。客户端失联读取操作详情。超时、5xx、崩溃或响应无法持久化转 unknown，租约过期只允许核实，迟到响应按尝试标识及状态条件写入。未知状态阻止再次外发及释放活动槽。核实只读 GitLab；无法确认则留待人工，保存证据。已确认失败才允许用新命令重试未完成项，原操作保留。换人接手使用新操作者的凭证和审计身份。

回退使用操作专属分支名及可检索的 MR 标识，分别检查分支、已产生的回退提交和源/目标 MR；已有同名但不符合预期的资源报冲突。Tag 写入前预查所有仓库，随后逐仓按冻结 SHA 创建并读取其最终提交核实。已存在且指向同一 SHA 记录“沿用并核实”，不同 SHA 阻塞且不得覆盖。最后复核全体 Tag，再提交归档。跨仓没有分布式事务，事实按仓库记载；归档后远端管理员仍有能力移动或删除 Tag，本地冻结历史持续保留。审计记录行动人、远端账号、目标、操作/清单 ID、受控原因和结果，不记录配置正文、脚本、Markdown 或私密链接。

## 7. HTTP 与页面契约

API 前缀 /api/v1。下表 V 代表 /projects/{projectId}/variants/{variantId}，R 代表 V/releases/{releaseId}。创建返回 201，更新/命令返回 200，已接受仍执行中的远端操作返回 202 和操作地址。列表 page/page_size、权限提示及错误结构沿用 [HTTP 约定](api.md)。

| 方法和相对路径 | 请求与结果 |
| --- | --- |
| GET /projects/{projectId}/workspace | 项目成员与系统管理员可读；返回 repository_count，前 10 条活动 variants、进行中 releases、结果待核实 attention，各组含真实 total/page/page_size/can_manage。只读聚合，不触发远端操作。 |
| GET /projects/{projectId}/releases | 项目范围跨产品分支分页。q 搜索名称/版本号/Tag，variant_id 可选且须属于该项目；status 默认 active（排除 archived/terminated），支持 all、attention 和实际发布状态。attention 指仍占活动槽的 unknown 操作。返回发布 ID、产品分支 ID/名称/编码、name（始终为字符串）、版本/Tag、状态、更新时间与 needs_attention。不可见项目及跨项目产品分支返回 404。 |
| PATCH V/release-settings | {tag_prefix}，产品分支 If-Match；返回新 ETag 和 Tag 示例。 |
| GET、POST V/releases；GET、PATCH R | 列表支持状态及名称/版本号/Tag 搜索；创建传 version_label、可选 name、description_md，读取 DTO 始终包含字符串 name。产品分支列表与详情同时返回布尔值 needs_attention，与项目列表共用“仍占活动槽的 unknown 操作”口径；运行中及不再占槽的历史未知操作不计入，不改变发布阶段或列表总数。PATCH 省略 name 保持原值，空串清除自定义名称，null 返回字段错误。草稿列表与历史可分页；详情状态、操作和材料能力通过独立工作流/材料接口读取。 |
| POST R/scope-preview、R/refresh-scope；PUT R/repositories/{id}/baseline | 预览给出范围 token、增减、最新基线和阻塞原因。显式刷新写入草稿，自定义基线传 ref 并返回解析后的 SHA。 |
| GET R/repositories/{id}/mr-options；POST R/changes；PATCH R/changes/{id} | 远端候选分页，录入 MR/直接提交或处置原因，排除跨范围仓库。关联已有回退 MR 提交原 change_id、repo 和 IID。 |
| POST R/items；PATCH、DELETE R/items/{id}；PUT R/sql-order | 上传材料用 multipart（metadata、file），配置用 JSON（format、mode、target_path、content 等）。替换文件或修改目标产生新修订。DELETE 仅移出；排序提交完整活动 SQL ID 数组。 |
| GET R/items/{id}/revisions；GET R/items/{id}/revisions/{revisionId}/file | 分页修订历史及单文件下载，包括已移出的历史材料。 |
| POST R/start、R/merge、R/create-revert、R/reconcile、R/archive | start 凭确认后的 scope_token 和基线预览开始占用。merge 指定有序 change_ids 和期望源 SHA；create-revert 指定原项。外发命令传 Idempotency-Key；reconcile 指定 operation/step 只读核实；archive 指定通过的 manifest_id、digest。 |
| GET R/operations、R/operations/{id} | 分页明细，显示每仓/每 MR 的成功、失败、结果未知及原因，返回可核实/可重试项。 |
| POST R/freeze、R/review、R/return、R/terminate | freeze 绑定核对过的候选 SHA 与内容版本；review 传 manifest_id、digest、pass/return 和说明；return 用于通过后首次打 Tag 前撤销；terminate 传原因及残留项确认摘要。 |
| GET R/manifests、R/manifests/{id}、R/manifests/{id}/entries、R/manifests/{id}/download | 历次冻结、验收说明、分页明细与 ZIP。manifest.json 可随包流式生成。项目成员可按冻结项下载其修订。 |
| POST /admin/maintenance/temp-files/preview、/admin/maintenance/temp-files/clean | 系统管理员按来源和分页预览。clean 提交预览标识及所选候选 ID，服务端复核后返回逐项结果。 |

当前客户端使用以下已注册接口。上表中汇总型读取与变更写入对应这些具体路径：

- 项目及产品分支发布查询中的 `%`、`_`、`!` 按字面值匹配，不能作为通配符扩大范围。创建发布仍不支持幂等键；网络失联时先按产品分支和版本号查询并核对已创建记录，不盲目重发。名称不代替必填版本号；名称字段错误为 422，非管理员改名为 403，当前阶段或父对象已归档为 409，陈旧 ETag 为 412。

- GET R/workflow 一次返回变更、送验版本、操作历史及最近操作步骤。GET R/manifests/{id} 返回头和逐项快照，末尾追加 /download 可下载。GET R/removed-items 与 GET R/items/{id}/revisions 支持分页。
- 仓库范围使用 POST R/scope-preview，再以返回的 token 放入 digest 调用 R/refresh-scope。POST R/baseline 接收 repo_id、可选 ref。首次建草稿用限时只读采集；未成功的仓库须手动确认基线。当前面板按单仓库、单个 MR 明确发起合并，同仓多项依次操作。过期基线与不完整差异阻止送验。
- POST R/mr-options 支持 page 和 page_size（默认 1/20，每页 10/20/50/100），返回候选数组，不提供总数；界面采用统一分页导航，总数未知时禁用末页，返回不足一页时禁用下一页。POST R/mr-options、R/select-mr、R/include-commit、R/remove-change、R/link-revert 分别查询候选、纳入 MR、补录提交、移出与关联回退。POST R/git-identity 显示目标仓库对应的 GitLab 账号。服务端逐项重新解析本人凭证。合并及回退操作使用 change_id，归档使用 manifest_id 和 digest，reconcile 使用 operation_id。幂等键在 HTTP 头传输。
- 送验先 POST R/freeze-preview 展示候选主干、未覆盖提交及配置冲突，再以 preview_token 作为 digest 调用 R/freeze。验收决策为 pass 或 return。归档重试只向缺少该 Tag 的仓库发送创建请求。
- 文件与在线配置共用 multipart 的 metadata 和 file 两部分；配置编辑器按 UTF-8 原文发送文件部分。仅修改元数据可省略 file。系统临时维护接口接受 source=releases，clean 提交经预览的候选 id/token。当前只登记发布来源，进行中的上传与已绑定文件均不列为候选。

缺少写前提为 428，陈旧版本为 412。范围或主干在确认后变化、并发发布冲突、材料冲突、额外提交未处置、同名异 SHA Tag 返回 409 及可定位的项目内条目。文件超限 413；字段或配置语法错误 422，含条目、字段及适用时行列号。远端权限/凭证失败按仓库列出受控原因；不可见项目不暴露名称。下载失败明确提示重试同一冻结版本。非幂等写入的前端不能以超时判定失败并自动重发。

项目顶层提供跨产品分支「发布」列表，创建时先选择产品分支；缺少 Tag 前缀时先配置前缀，再填写名称、版本和说明。原产品分支详情的「发布」入口和深链接继续保留。草稿/合并阶段默认打开仓库与 MR，验收及归档阶段默认打开验收工作区；用户显式选择的材料等页签写入 URL 并优先保留。列表与详情以名称为主标题，未填写则显示版本号；版本/Tag、状态和产品分支作为辅助信息。详情将协作草稿、当前验收版、历史送验版显式区分，按仓库呈现基线到候选的差异。材料按类别分组，SQL 顺序可用键盘调整，配置预览可定位冲突双方。合并/撤回/打 Tag 前展示远端身份、具体目标及范围，操作结果可在重新打开页面后继续查看。深浅主题、窄屏、键盘、未保存保护及回跳兼容遵循 [前端规范](frontend.md)。

## 8. 验收与限制

运行迁移、服务与页面已交付；GitLab 不同实例版本、保护规则和个人令牌授权以实际实例联调为准。验收至少覆盖下列可观察结果：

- 发布名称的 Unicode 长度、首尾空白、空值回退、PATCH 省略/清空/null、管理员权限、各阶段和父对象归档限制；名称修改不改版本与 Tag，旧 ETag 与旧冻结预览不可复用。
- 项目及产品分支列表按名称/版本/Tag 搜索和通配符字面转义；名称编辑保留历史版本、Tag、冻结清单及摘要，已冻结 ZIP 使用冻结名称；退回后改名不改变上一轮 ZIP 标题。
- 两份草稿独立协作；同一产品分支抢占、跨项目同仓同主干抢占只有一方成功，不同主干可并行；多仓抢占失败全部回滚。
- 首次默认与自定义基线、等待期间已有新归档、主干被强推、零 MR 纯材料发布、直接提交与部分合并、外部合并及两种回退入口。
- 两人编辑同一材料冲突可恢复；元数据修订复用字节；SQL 排序与旧包一致；退回换文件后仍可读上一轮；无范围或未处置差异不能送验。
