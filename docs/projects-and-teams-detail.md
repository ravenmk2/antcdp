# 项目与团队详细设计

更新日期：2026-10-27。状态：基础业务、正式页面、图标与快捷方式已落地并进行隔离验证；尚未完成全部验收矩阵，实际进展见 [开发说明](development.md)。需求来源见 [项目与团队设计](projects-and-teams.md)。SQL 阅读副本见 [项目与团队 DDL](projects-and-teams-schema.sql)，不作为运行迁移执行。

### 当前实现与目标契约

以下章节保留完整目标设计；当前运行接口以本段差异说明和代码为准，避免把规划能力当成已交付能力。

- 项目和团队使用共享的 `collaboration` 业务模块与仓储端口，保留独立数据库实体；身份校验与事务仍由 identity 统一执行。
- 资源 DTO 采用扁平字段 `icon_key`、`icon_file_id`、`direct_role`、`is_member`、`can_manage`、`etag`、`membership_etag`；列表为 `data:{items,total,page,page_size}`。成员读取同样分页并提供 `membership_etag`，有效成员包含 `direct_role`、`effective_role`、`sources`。关系命令和生命周期命令返回 204，界面随后重新读取资源和关系。
- 图标上传路径为 `POST /icon-uploads`，删除草稿为 `DELETE /icon-uploads/{id}`，预览与已绑定文件通过 `GET /icons/{id}`。读文件始终验证当前绑定对象的访问权；项目参与者可读取该项目授权团队的图标，不能借此访问团队成员详情。写入形式为 `icon:{type:"default"}`、`{type:"builtin",key}` 或 `{type:"upload",file_id}`。内置目录 `GET /icon-catalog` 返回稳定 key 列表。
- 成员/团队选择器支持 q 搜索，当前最多返回 50 个正常候选，并排除已有直接成员或团队授权；尚未实现选择器分页和目录图标预览。初始管理员选择器是 `GET /admin/collaboration/user-options`，团队选项只返回 ID、编码、名称和摘要。
- 快捷方式通过上下按钮排序；跨设备冲突不自动覆盖。Markdown 禁止原始 HTML 和图片嵌入。成员分页目前在应用层合并有效来源之后执行；大规模查询优化、账号删除的逐对象成员审计及完整业务并发压力验收仍需后续完成。
- 页面按已确认预览采用项目卡片、团队列表和控制台表格。列表/详情固定入口读取最新快捷方式分组后按 ETag 写入；冲突重新读取并要求重做，不自动覆盖。侧栏管理弹窗仍采用草稿编辑后保存，尚未改成目标设计的即时保存。成员 DTO 尚无头像字段，页面使用统一默认头像；控制台不显示无完整数据来源的管理员名单。

## 1. 边界与设计取值

本稿覆盖资料、成员、团队授权、生命周期、图标、工作区快捷方式及控制台管理。不包含任务、仓库、动态角色、内容图片上传、通知和业务活动流。

已确认的决策包括独立 icon_file、编码保留大小写且唯一比较忽略大小写、项目和团队名称分别唯一、团队只提供项目成员权限、所有管理员可退出、两套导航、可排序的个人快捷方式，以及分组加号悬停显示。

为使接口和 DDL 可评审，以下沿用此前建议作为**设计默认值，尚未视为用户逐项确认**：

| 项目 | 本稿默认值 | 调整影响 |
| --- | --- | --- |
| 编码 | 创建后不可改，2–64 位，首尾字母或数字；不复用 | 字段校验、PATCH 契约；不影响 ID 关联 |
| 名称 | trim 首尾空白，1–100 码点，忽略大小写但区分重音；结束后仍占用 | 校验与唯一索引排序规则 |
| 摘要/简介 | 选填，300 码点 / 100 KiB UTF-8，空字符串 | 请求限制与字段校验 |
| 归档退出 | 本人可退出，管理性成员变更需恢复项目 | 生命周期权限 |
| 解散恢复 | 不提供，保留团队墓碑和图标 | 生命周期 API |


原型的示例自动固定项和简化 Markdown 渲染只用于演示，不作为正式实现契约。

## 2. 模块与数据模型

新增 project/team 领域模块，media 增加独立 IconFile 用例；identity 删除账号事务接入小范围成员清理端口。复用现有 UnitOfWork、sqlx 适配器、审计追加器，不让模块服务相互调用并开启独立事务。

九张表职责维持需求稿的划分，其中三张负责账号级侧栏偏好。所有表为 InnoDB；ID、版本以 BIGINT UNSIGNED 存储，API 为字符串；时间 UTC DATETIME(3)。ID 是稳定身份，code 供展示和查询，不使用名称或编码做关联键。

### 2.1 主表和文件

project/team 共同字段：id、code、name、summary、description、icon_key、icon_file_id、created_by_user_id、row_version、membership_version、created_at、updated_at。project 加 archived_at；team 加 dissolved_at，不额外存重复状态。DTO 根据时间派生 status。

- code 使用 ascii_general_ci，数据库保存原始大小写，独立唯一索引；应用正则 `^[A-Za-z0-9][A-Za-z0-9_-]{0,62}[A-Za-z0-9]$`，拒绝非 ASCII 和隐含空白，不自动改写。
- name 使用 utf8mb4_0900_as_ci；应用 trim 后验证，不折叠中间空格；以数据库唯一约束为最终依据。`Cafe` 与 `CAFE` 冲突，`Café` 与 `Cafe` 可不同；在目标 MySQL 验收。
- summary 与 description 非空，可为空字符串；description 不建立全文索引，也不存 HTML 副本。
- icon_key 与 icon_file_id 最多一个非空；均空表示默认图标。只有代码白名单中的稳定 key 可写入，显示名称可以变而 key 不变。
- 一个文件只能被一个项目或团队绑定。两张主表各自 UNIQUE(icon_file_id) 只保证表内唯一，跨表互斥必须锁定文件并验证 staged 状态。
- archived_at/dissolved_at 索引支持状态列表；名称/编码唯一索引也用于精确匹配。列表统一 created_at DESC, id DESC。搜索名称、编码、摘要使用转义后的参数化 LIKE，`%`、`_` 作为普通输入，不把编码中的下划线当通配符。ASCII 编码列及用户选择器的用户名列先转换为 utf8mb4 再比较，支持中文及 emoji 关键词，编码匹配仍不区分大小写。
- 无成员数、有效权限或管理员数缓存列。初期查询计算，后续有测量证据再优化。
- 创建者和文件上传者关联用户墓碑；不设置物理外键，由应用事务校验引用，不使用业务对象级联硬删除。

icon_file 继续只处理图标：256×256 PNG，保留上传者、随机 storage_key、尺寸、字节数、sha256、staged/attached/orphaned 状态及对应时间。不扩展为内容图片或缩略图模型；avatar_file 不迁移不改名，两个用例可共用图像处理函数和存储接口。

### 2.2 关系表

| 表 | 主键 | 角色 | 反向索引 |
| --- | --- | --- | --- |
| project_member | project_id, user_id | admin/member | user_id, project_id |
| team_member | team_id, user_id | admin/member | user_id, team_id |
| project_team | project_id, team_id | 固定成员，不存 role | team_id, project_id |

成员表记录 created_at、updated_at；授权表记录 created_at。移除直接删除关系行；重新加入产生新时间。历史审计独立保存。

项目有效角色：直接 admin → admin；直接 member 或至少一个正常团队的成员关系 → member；否则无业务权限。系统管理员具有独立的全系统管理资格，不写入成员关系。团队管理员在项目内仍只继承 member。

有效成员列表按 user_id 去重，保留全部来源。禁用账号仍显示在管理列表并标记“已禁用”，但不计入 active_member_count；删除账号移除关系，不显示在现行成员列表。member_count 表示去重后保留的成员人数，active_member_count 表示可访问的正常账号人数；两者均不把系统管理员旁路计为成员。直接管理员数量可包含禁用用户，另提供 active_admin_count，零可用管理员时提示系统管理员接管。

### 2.3 侧栏持久化模型

固定及排序现已确定为账号级服务端数据，跨设备共享；不再采用第一个草案的本机偏好方案。

| 表 | 字段 | 约束与索引 |
| --- | --- | --- |
| user_sidebar_preference | user_id、project_version、team_version、updated_at | user_id 主键及 user 逻辑引用，两个版本初始 1 |
| user_project_shortcut | user_id、project_id、sort_order、created_at | 联合主键；(user_id, sort_order, project_id) 排序索引；(project_id, user_id) 清理索引 |
| user_team_shortcut | user_id、team_id、sort_order、created_at | 联合主键；(user_id, sort_order, team_id) 排序索引；(team_id, user_id) 清理索引 |

快捷表 user_id 引用 user_sidebar_preference.user_id，再通过该表关联 user，保证每个快捷关系都有版本行；目标 ID 分别关联 project/team，不使用多态 target_id。应用事务校验版本行和目标存在，删除时明确清理引用。

sort_order 使用 INT UNSIGNED，从 1 开始；同组排序值不设置唯一约束，避免交换顺序时的中间冲突。查询按 sort_order ASC、目标 ID ASC；增删或排序后在同一事务内重新编号为 1..N，保留已有记录的 created_at。默认空分组，不自动固定。

升级迁移为所有未删除用户补一条 preference 行，不插入快捷方式；未来安装创始人、注册及管理员建号在账号创建事务中一并建 preference。已删除用户不补行。正常用户缺行属于数据完整性问题，不在 GET 中隐式建行。一行两版本使空分组也能检测并发变化；修改项目组不递增团队组版本。无变化不更新时间和版本。

账号禁用只停止访问，保留偏好；删除账号时依次删除快捷记录、preference，再保留原 user 墓碑。归档项目保留快捷方式，解散团队删除其快捷关系。直接退出/移除、团队退出/移除、团队解散、项目团队撤权后，对受影响用户重新计算全部授权来源：仅在不再是项目成员时删除对应项目快捷关系，不能因撤销其中一种来源而全部清掉。

以上自动清理与成员关系变更在同一事务内完成，每个受影响用户/分组最多递增一次版本；受影响但没有待删快捷方式的分组不递增。清理资格依据关系存续及团队解散状态，不依据暂时禁用的账号状态。系统管理员全局旁路不算成员资格。

批量撤权先发现可能影响的用户（团队成员及相关快捷持有人），按全局锁顺序锁相关用户，再锁团队/项目并重新校验集合；新增早序用户则整体回滚并有界重试。偏好行统一在业务对象和文件锁之后按 user_id 升序锁定；快捷方式写操作同样先用户、团队、项目，再偏好行，禁止相反锁序。必须覆盖“固定与退出”“排序与自动清理”“解散与新增成员”竞争测试。

GET 仍按当前关系过滤并且不返回无权限对象；不依赖客户端报告 invalid_ids 才撤权，不通过 GET 改数据库。若发现历史脏记录，记录维护信号并交由同一锁序的修复用例处理。临时数据库失败不能触发清空。

## 3. 页面范围与权限矩阵

工作区默认 mine，控制台默认 all。工作区页面只打开自己参与的对象，即使操作者为系统管理员；系统管理员可进入控制台处理其他对象。前端页面位置不是授权凭据，服务端始终验证账号、会话及资源角色。

| 操作 | 普通成员 | 直接业务管理员 | 系统管理员 |
| --- | --- | --- | --- |
| 查看参与对象、成员来源 | 可 | 可 | 可 |
| 查看不参与对象 | 不可 | 不可 | 控制台可 |
| 编辑资料、图标 | 不可 | 正常状态可 | 正常状态可 |
| 添加/移除直接成员、改角色 | 不可 | 正常状态可 | 正常状态可 |
| 添加/移除项目团队 | 不可 | 项目正常时可 | 项目正常时可 |
| 退出个人直接关系 | 可 | 可，包括最后一位 | 本人有直接关系时可 |
| 创建对象 | 不可 | 不可 | 控制台可 |
| 项目归档/恢复、团队解散 | 不可 | 不可 | 控制台可 |
| 系统审计 | 不可 | 不可 | 可 |
| 固定到个人侧栏 | 本人参与对象 | 本人参与对象 | 本人参与对象 |

系统管理员在工作区只展示其业务角色可用操作；进入控制台后展示系统管理能力。受限改密会话、禁用及删除账号不能使用这些接口。

团队成员能看到所在团队的成员名单及自己可见的关联项目；项目成员可看到项目有效成员和来源团队标签，但不能因此读取来源团队详情或整个团队成员名单。项目管理员可搜索团队目录的有限信息以授权，不能绕过团队详情权限。

## 4. HTTP 契约

以下均相对 `/api/v1`。采用现有 data 包装、error.details、CSRF、Cache-Control:no-store 和会话策略；新增接口在实现前不视为可调用。

### 4.1 查询与基础命令

| 方法与路径 | 含义 | 条件 |
| --- | --- | --- |
| GET /projects、GET /teams | 列表 | scope=mine（默认）/all，all 仅系统管理员 |
| GET /projects/{id}、GET /teams/{id} | 详情 | 成员或系统管理员 |
| POST /projects、POST /teams | 创建并设置初始管理员 | 系统管理员 |
| PATCH /projects/{id}、PATCH /teams/{id} | 修改资料/图标 | 正常对象管理员；资料 If-Match |
| POST /projects/{id}/archive | 归档 | 系统管理员；资料 If-Match |
| POST /projects/{id}/restore | 恢复 | 系统管理员；资料 If-Match |
| POST /teams/{id}/dissolve | 解散 | 系统管理员；解散确认版本，见第 5 节 |

列表参数：q 最大 100 码点；status=active/archived/all（团队为 active/dissolved/all），默认 active；page 从 1 起，page_size 为 10/20/50/100，默认 20。返回 items、total、page、page_size；按当前权限再筛选，不先分页后过滤。mine 不返回已解散团队，因为解散已清除成员关系。归档项目仍可出现在 mine。

创建请求示例（team 同结构）：

```json
{
  "code": "AntCDP_Web",
  "name": "协作平台",
  "summary": "团队共同工作的地方",
  "description": "## 项目目标\n完善基础协作能力。",
  "icon": { "type": "builtin", "key": "box" },
  "admin_user_ids": ["1", "4"]
}
```

初始管理员列表去重后至少 1 位，最多 100 位，全部必须为正常未删除账号；不自动加入创建者。创建、关系、图标绑定、审计一次事务提交。返回 201 和详情，Location 指向 ID 地址。网络中断不自动重新 POST；以精确 code 查询列表核对创建结果，禁止靠同编码请求覆盖现有对象。

PATCH 只接受 name、summary、description、icon；code 不可提交。字段缺省保留原值，文本 null 非法。icon 为三个互斥结构之一：`{"type":"default"}`、`{"type":"builtin","key":"box"}`、`{"type":"upload","file_id":"42"}`。未知字段、混合字段或非法 key 返回 422。保持当前文件引用属于无变化，不要求它重新成为草稿；切换到其他文件必须验证有效草稿。

详情示例（省略时间和计数）：

```json
{
  "data": {
    "id": "21", "code": "AntCDP_Web", "name": "协作平台",
    "summary": "团队共同工作的地方", "description": "## 项目目标",
    "status": "active", "archived_at": null,
    "icon": {"type":"builtin","key":"box"},
    "version": "3", "membership_version": "7",
    "membership_etag": "\"project-members-21-v7\"",
    "access": {"is_member":true,"direct_role":"admin","effective_role":"admin"},
    "capabilities": {"edit":true,"manage_members":true,"archive":true,"leave":true}
  }
}
```

capabilities 表示服务端能力，UI 再结合工作区/控制台隐藏对应入口；不能由客户端传入 capabilities 作为权限。DTO 不暴露 storage_key 和磁盘路径。列表不含 description，包含图标、状态、成员计数及当前业务角色。

### 4.2 成员与团队授权

| 方法与路径 | 请求/响应要点 |
| --- | --- |
| GET /projects/{id}/members | view=effective（默认）/direct；q/page/page_size 同列表 |
| GET /teams/{id}/members | 直接成员，分页搜索 |
| POST /projects/{id}/members、POST /teams/{id}/members | `{user_id, role}`，单个添加 |
| PATCH /projects/{id}/members/{user_id}、团队同形 | `{role}`，只改直接角色 |
| DELETE /projects/{id}/members/{user_id}、团队同形 | 删除直接关系 |
| POST /projects/{id}/leave、POST /teams/{id}/leave | 空对象，操作当前用户；不接收 user_id |
| GET /projects/{id}/teams | 当前团队授权，分页 |
| POST /projects/{id}/teams | `{team_id}`，不接受 role |
| DELETE /projects/{id}/teams/{team_id} | 撤销团队来源，保留其他来源 |
| GET /teams/{id}/projects | 先验证团队详情权限，再返回调用者可见的关联项目 |

所有成员命令使用所属对象 membership_etag；leave 不要求版本，锁定后幂等删除当前用户自己的直接关系，返回 204。已无直接关系时，只要调用者仍为有效登录用户，leave 仍返回 204，不返回对象存在性或资料；不存在的 ID 同样不泄露信息。leave 不删除团队间接来源。

添加已存在且角色相同的直接成员视为无变化；角色不同返回 409 MEMBER_ALREADY_EXISTS，要求显式改角色。重复加入项目团队视为无变化；删除已不存在的直接关系在授权及版本检查后返回成功，无重复审计。成功成员命令返回 200，data 包含 membership_version 和 membership_etag；有效成员列表重新读取，不能在客户端凭本次操作推算所有间接权限。

有效成员投影：user_id、username、display_name、avatar_url、account_status、direct_role（可空）、effective_role、sources。sources 条目为 `{type:"direct"}` 或 `{type:"team",team_id,team_name,team_code}`，按团队 ID 稳定排序；同一用户只出现一次。禁用用户保留角色来源，但不得因此被授权。

### 4.3 有界选择器

不向业务管理员开放既有 `/admin/users`：新增资源范围的选择器。

- `GET /projects/{id}/member-options`、`GET /teams/{id}/member-options`：该对象管理员可搜索正常用户，只返回 ID、用户名、显示名称、头像；排除已直接加入者。团队继承用户仍可作为直接成员添加。
- `GET /projects/{id}/team-options`：项目管理员搜索正常、尚未授权的团队，只返回 ID、编码、名称、摘要、图标 URL 和成员数，不返回成员明细。
- `GET /admin/collaboration/user-options`：系统管理员创建对象时选择初始管理员，同一用户白名单投影。

选择器 q/page/page_size 与列表一致，默认 20，最多 50；对象需正常且可管理。提交时重新验证状态，不信任选项快照。图标 URL 使用对应选择器资源路径，如 `/projects/{id}/team-options/{team_id}/icon`，每次读取验证项目管理权和团队可选性，不因知道 icon_file ID 而放开整个文件接口。

### 4.4 图标

| 路径 | 用途 |
| --- | --- |
| GET /icon-catalog | 已登录用户读取内置稳定 key 和中文名称 |
| POST /projects/{id}/icon-drafts、POST /teams/{id}/icon-drafts | 正常对象管理员上传 multipart file |
| POST /admin/collaboration/icon-drafts | 系统管理员创建对象前上传 |
| GET /icon-drafts/{file_id} | 上传者预览有效草稿 |
| DELETE /icon-drafts/{file_id} | 上传者取消未绑定草稿，已绑定文件返回 409 |
| GET /projects/{id}/icon、GET /teams/{id}/icon | 按对象可见性读取已绑定文件 |

只读草稿和文件也验证有效会话，改密受限会话不可访问。图片响应 `Cache-Control: private, no-cache`，每次复用需授权再判断 ETag；权限撤销后不能用 304 绕过校验。旧资源图标 URL 读取的是当前绑定文件，不暴露磁盘或公共静态目录。

浏览器裁剪后上传；服务器重新解码、校验、去元数据和编码。输出 256×256 PNG，文件上限沿用需求稿。草稿 24 小时，孤立文件 24 小时后清理。文件生命周期与引用更新同事务；磁盘先写、元数据后提交，失败遗留由现有安全扫描方式回收。团队解散保留图标用于控制台历史展示，不误标 orphaned。

本阶段不支持 SVG 上传或 Markdown 内容图片上传。Markdown 图片语法先不加载远程图片，渲染替代文本；链接只接受 http/https，禁用原始 HTML、脚本协议和嵌入内容。

### 4.5 侧栏快捷方式 API

| 方法与路径 | 契约 |
| --- | --- |
| GET /me/sidebar-shortcuts | 返回 projects/teams 有序摘要、两个分组版本与编辑令牌；从会话取用户 |
| PUT /me/sidebar-shortcuts/projects | `{ "ids": ["21", "23"] }` 整组期望顺序，项目组 If-Match |
| PUT /me/sidebar-shortcuts/teams | `{ "ids": ["11"] }` 整组期望顺序，团队组 If-Match |

每组最多 200 个不重复 ID；空数组表示清空该组，省略 ids 非法。固定、取消、排序统一为整组替换命令，事务中验证全部成员资格并校验分组令牌。对象不存在、不再可见或已解散时整次失败，返回 422 VALIDATION_FAILED / details.code=shortcut_target_unavailable，只定位 ids 下标，不泄露对象信息；重复 ID 返回字段校验错误。归档项目只要仍是成员就可固定。

响应按 data 包装，projects/teams 分别包含 items、version、etag；item 为 id、code、name、icon、status、sort_order，名称等由实时对象查询补充，不存入快捷表。组令牌为 `"sidebar-projects-<user_id>-v<version>"` / `"sidebar-teams-<user_id>-v<version>"`；仅作为编辑前置条件，不对动态摘要做 HTTP 304。

PUT 成功返回该组当前内容和新令牌，未修改另一组；无变化返回原版本。缺少 If-Match 428、格式错误 422、旧版本 412，不能用 `*` 覆盖。前端冲突后重新读取，提示在最新列表重新操作，不静默重放旧的整组数组。账号在两个设备交替操作时因此不会覆盖未看到的变更。

GET/PUT 均要求正常完整会话；PUT 需 CSRF。响应 no-store；网络中断先 GET 判断结果，不能自动重复旧 PUT。快捷方式变更不撤销登录会话。原先 `/me/collaboration-shortcuts/resolve` 方案作废。

## 5. 并发、缓存与错误

资料 ETag：`"project-21-v3"` / `"team-11-v2"`，仅标识可编辑基础字段与生命周期，不包含实时成员计数或权限。详情响应带该编辑令牌但 no-store，不使用它对整份动态 DTO 返回 304。

成员编辑令牌：`"project-members-21-v7"` / `"team-members-11-v4"`。成员读取返回 membership_etag 字段；它不作为完整有效成员响应的 HTTP 缓存 ETag，因为团队成员和用户资料可独立变化。团队成员变化不批量更新项目成员令牌。

解散确认令牌同时覆盖团队资料和成员版本：详情的 dissolve_etag 为 `"team-dissolve-11-r2-m4"`，解散请求使用 If-Match；否则确认期间新增成员不会被版本检测发现。归档仅需资料版本，原子检查状态并禁止后续管理性变更。

需要版本的命令：缺少 If-Match → 428；非法格式或弱 ETag → 422；过期 → 412。先重查授权，再返回版本信息；不对无权调用者泄露当前版本。

| 情况 | 状态/错误码 | 前端处理 |
| --- | --- | --- |
| 资料校验失败 | 422 VALIDATION_FAILED，details 指定字段 | 保留输入，定位字段 |
| 编码/名称冲突 | 409 CODE_CONFLICT / NAME_CONFLICT | 对应字段提示，不回显冲突对象资料 |
| 对象归档/解散不可写 | 409 RESOURCE_READ_ONLY | 保留草稿，刷新状态 |
| 草稿过期、已绑定 | 409 ICON_DRAFT_UNAVAILABLE | 重新选择/上传 |
| 已存在且角色不同 | 409 MEMBER_ALREADY_EXISTS | 刷新成员，用角色编辑操作 |
| 详情不存在或不可见 | 404 RESOURCE_NOT_FOUND | 清理入口，返回列表 |
| 对象可见但无管理权 | 403 FORBIDDEN | 移除管理控件 |
| 版本冲突 | 412 VERSION_CONFLICT | 保留本地输入，重新读取后人工重提，不自动覆盖 |
| 会话失效 | 401 | 清理当前视图，回登录页 |

名称/编码唯一索引覆盖归档和解散墓碑。无变化的写入不递增版本，不重复审计。POST 创建无自动重试；其余修改网络结果未知时先读当前状态，再判断是否重提。

JSON 默认 64 KiB 不能容纳 100 KiB 简介及转义开销，项目/团队创建与资料 PATCH 单独设 **1 MiB 请求体上限**，解析后仍按简介 UTF-8 100 KiB 限制；其余接口沿用原上限。上传接口按文件 2 MiB 加有限 multipart 开销限制。

## 6. 事务实施规则

遵循现有 identity 的用户/会话锁规则，跨模块整体顺序：相关 user 按 ID 升序 → 当前 session（如需）→ team 按 ID 升序 → project 按 ID 升序 → icon_file 按 ID 升序。不在获得后序锁后补取更早对象锁；发现额外早序对象时回滚并以完整集合有界重试。

| 用例 | 原子操作 |
| --- | --- |
| 创建 | 锁操作者与初始管理员用户；验证状态；插入对象及管理员；绑定草稿；审计 |
| 改资料/图标 | 锁操作者、对象和新旧文件；重查权限/版本；更新资料与文件状态；审计 |
| 加人/改角色/移除 | 锁操作者及目标用户，再锁对象；验证直接角色、状态和集合版本；改关系、递增集合版本、审计 |
| 添加/移除团队授权 | 锁操作者、目标团队、项目；重查项目直接管理权及团队状态；改关联、递增项目成员版本、审计 |
| 本人退出 | 锁本人和对象；删除直接关系、递增成员版本、审计；允许最后管理员退出 |
| 解散团队 | 锁操作者、团队；重新读取关联项目并依次锁定；验证组合令牌；清空关系，更新团队及受影响项目成员版本；审计 |
| 删除账号 | 沿用账号墓碑事务，扩展锁其相关团队和直接项目；删除两类直接成员关系、递增对应集合版本；不删除 project_team |
| 图标清理 | 只锁文件元数据，再用普通读确认两张主表均无引用；状态、文件行锁和引用复查共同保护；不反向锁业务对象 |

直接角色变更与资料编辑以同一对象行锁串行；团队授权写入需先锁团队，解散持有团队锁后关联集合稳定。账号加入任何对象前必须锁目标用户，因此删除用户持有该用户锁后其成员集合不会新增。文件绑定只能从 staged 转 attached，清理不能仅依据事务外扫描结果删除。

团队成员变化与间接访问检查使用同一团队锁；如果操作需要依赖间接权限（例如归档项目中的查看授权一致性），先发现候选来源，按顺序加锁后重新验证。读权限以本次授权快照为界，无法撤回已经发送到浏览器的数据；变更提交后的新请求必须使用新关系，禁止会话缓存成员身份。

成员变动只增加 membership_version，不更新资料 row_version/updated_at；生命周期及资料变化更新 row_version/updated_at。解散同时增加两类版本。归档项目仍允许团队变化、账号删除和本人退出减少有效成员。

死锁/锁等待只在整个数据库用例边界有界重试，不在重试中重复上传磁盘文件。审计与业务一起提交，任何失败整体回滚。大团队解散与用户删除须按实际规模测试事务耗时，不以拆分非原子清理换取表面成功。

## 7. 具体页面与交互

本节的路由、权限、数据含义、保存语义和确认流程为交互契约；布局、密度、尺寸及字段排列描述当前方案，按 [UI 规范的约束分级](ui-design.md#规范的适用方式) 随内容和设备优化，不作为新页面的固定模板。目标能力与当前实现的差异见本文开头。

### 7.1 路由和布局

| 工作区路由 | 页面 |
| --- | --- |
| /home | 沿用首页，新增常用项目/团队入口区 |
| /projects | 我参与的项目列表 |
| /projects/:id | 概览；?tab=members/teams |
| /teams | 我参与的团队列表 |
| /teams/:id | 概览；?tab=members/projects |

控制台对应 /admin/projects、/admin/projects/:id、/admin/teams、/admin/teams/:id。链接使用 ID，避免未来编码调整破坏地址。业务角色不能访问 /admin。详情共用组件，布局与操作集按入口决定；未知 tab 回到概览。

列表顶部沿用导航标题，不增加重复大标题。工作区项目使用卡片、团队使用横向列表，控制台统一表格；提供状态页签、600ms 搜索、计数与分页。计数按当前 scope/q/unmanaged 分别读取正常与结束状态的 total，并合计全部，不以当前分页条数估计。工作区提供固定操作，控制台提供创建操作及“仅显示无有效管理员”筛选（API 布尔参数 unmanaged，仅 scope=all 可用）。

详情头部组织图标、名称、编码、状态、摘要及能力对应操作；页签与 query 同步。概览显示 Markdown 和基本信息；项目成员页展示合并来源，参与团队单独页签；团队页展示直接成员和“加入项目”（调用者可见的已加入项目）。成员来源较多时按行宽折叠并可展开查看全部，其直接角色操作放到行菜单；编辑资料、刷新、退出、归档/恢复与解散收纳到头部更多菜单，菜单宽度随内容自适应，固定入口保留在头部；所有可访问详情的用户都可刷新，编辑仍受管理权限限制。不展示任务、仓库等空模块，也不从成员分页推断完整管理员名单。

### 7.2 侧栏快捷方式

- 分组标题为项目、团队，只作标签，不跳转列表；侧栏不提供“查看全部项目/团队”。用户菜单提供“我的项目”“我的团队”，进入工作区的本人参与列表；控制台中使用这两个入口同样返回工作区，控制台独立的项目管理/团队管理导航保留。**桌面鼠标未经过标题行时加号透明且不可指针点击，经过整行时显示；加号占位保持，列表不跳动。**
- `:focus-within` 时同样显示，加号保留 Tab 顺序和“管理项目/团队快捷方式”的可访问名称；回车/空格打开。触屏或无悬停设备常显，不依赖长按发现。
- 分组加号打开管理弹窗：已固定列表、上移/下移、取消固定、可添加列表及搜索。**当前实现**是草稿编辑后保存，取消丢弃未保存调整。**尚未实施的目标**是变化即时保存、按钮为“完成/关闭”；实现此目标时才切换文案与保存行为，不把两种模式混用，也不因视觉改版擅自切换。
- 可固定对象必须本人参与；系统管理员也不能在个人快捷方式中固定仅凭全局权限可见的对象。列表/详情提供相同入口。
- 每组在数据库保存目标 ID 与 sort_order，不保存名称、图标 URL 或角色快照。服务端从会话确定 user_id，客户端不能指定其他用户；本地内存仅保留当次响应，不以 localStorage 作为权威数据。
- 启动和窗口重新获得焦点时 GET 账号快捷方式；所有固定、取消和排序由服务端验证成员关系与分组版本后持久化，每类最多 200 条。原 resolve 接口方案撤回，具体契约见第 4.5 节。
- 断网、503 或加载失败保留最后成功视图并显示重试，禁止用空列表覆盖服务端偏好。退出、解散成功后重新读取；多标签可广播失效通知再读取，跨设备通过重新聚焦和下一次操作刷新。版本冲突不得自动覆盖。
- 归档项目保留入口及“归档”标识；取消固定不退出对象；直接退出后仍有团队来源则入口保留。空分组显示“尚未固定”，加号仍可使用；完整列表通过用户菜单访问。首页内容区可保留列表入口，不属于侧栏重复导航。
- 中部导航独立滚动，账号固定底部；移动抽屉沿用现有焦点陷阱、Escape 关闭与焦点恢复规则。

### 7.3 表单、裁剪和确认

创建/编辑弹窗宽度按内容和视口确定，当前桌面约 660px 仅作参考；标题和操作区保持可达，正文超高时滚动。相关字段可在空间充足时并排，窄屏纵排；编码编辑态只读。摘要使用短文本域，创建时提供初始管理员多选，简介提供编辑/预览切换；按填写流程组织字段，保存失败保留文本。

图标区域显示当前图标，通过“更换图标”展开默认/内置/上传选择；内置图标显示可访问中文名称。裁剪弹窗支持拖动、缩放、位置滑块及方形预览。取消裁剪回到未变图标，取消资料不绑定草稿；草稿到期保存失败明确提示重新上传。切换图标不丢失名称、摘要、简介及已选初始管理员。

成员添加弹窗可搜索正常用户、选择 admin/member。个人直接角色与有效角色分别表达；只有团队来源时提供“添加为直接成员”，不允许直接移除该来源中的个人。移除团队提示影响人数与保留其他来源；人数是确认时快照，提交仍实时授权。

归档提示变为只读；解散提示删除全部团队关系且不可恢复，显示受影响项目数量并要求输入团队编码确认（比较忽略大小写）。最后管理员降级或退出提示将需系统管理员接管，但不阻止。归档项目退出作为例外仍可用。未加入对象的系统管理员不显示本人退出按钮。

## 8. 审计事件

动作前缀 project/team：created、updated、icon_changed、member_added、member_removed、member_left、member_role_changed；另有 project.team_added、project.team_removed、project.archived、project.restored、team.dissolved。

目标以项目或团队 ID 为主；detail 白名单保存关联 user_id/team_id、前后角色、编码名称快照、变化字段和成员数量。解散事件记录受影响项目 ID（规模限制与截断标记应在实现时明确），受影响项目各追加 team_removed，reason=team_dissolved；账号删除引起的 member_removed 标记 reason=user_deleted。禁止存全文简介、图片、凭据或任意请求体。

业务内容不因审计失败而提交。成员变更幂等无变化不记事件。快捷方式属于账号级个人偏好，持久保存但不写业务审计；成员/团队变更引起的自动清理由相应业务审计记录原因，不逐条写快捷清理事件。

| 归档与管理性变更竞争 | 按项目锁排序，归档后的变更失败 |
| 团队解散与新增项目授权竞争 | 不出现已解散团队仍有有效授权 |
| 同一图标同时绑定项目与团队 | 恰好一个成功，另一方冲突 |
| 清理草稿与绑定竞争 | 不删除已成功绑定文件 |
| 简介达到边界、包含脚本 HTML/链接 | 大小按 UTF-8 验证，不执行脚本 |
| 成员变化时编辑简介 | 不产生无关资料版本冲突 |
| 加号静止、悬停、键盘、触屏 | 静止隐藏；其他路径可发现且可操作，无布局跳动 |
| 快捷方式读取失败、权限撤销 | 暂时失败不删偏好；确定无权限才清理 |
| 系统管理员工作区/控制台切换 | 工作区 mine，控制台 all；普通用户不得切入 |
| 升级旧库、全新安装、图标磁盘失败 | 原头像不变；迁移一致；失败可恢复，不伪装成功 |
