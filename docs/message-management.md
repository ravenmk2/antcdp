# 消息管理设计入口

状态：当前版本前后端已实现，八张独立表包含于统一初始迁移，当前基线版本 1、共 48 张业务表。测试及发布边界见[开发说明](development.md)，不将协议模拟等同于真实供应商联调。

## 1. 模块边界

**邮件、短信、钉钉是三个独立业务模块，不共享业务逻辑和业务数据。** “消息管理”仅作为文档分类入口；控制台提供三个平级入口，不是统一发送模块。

| 模块 | 独立能力 | 详细设计 |
| --- | --- | --- |
| 邮件 | SMTP 配置、发件名称、邮件模板、邮件引擎注册/渲染、发送时附件、预览、发送测试、30 天发送日志 | [邮件管理](email-management.md) |
| 短信 | 供应商配置、短信模板、参数映射、短信引擎注册/渲染、本地模拟、发送测试、30 天发送日志 | [短信管理](sms-management.md) |
| 钉钉 | 群机器人配置、加签、关键词、文本/Markdown 测试、诊断 | [钉钉机器人管理](dingtalk-management.md) |

三类分别拥有应用服务、领域对象、仓储接口、数据表、适配器、API、前端功能和测试。禁止用一张表加 type 区分三类，禁止共享 MessageChannel/MessageTemplate、统一发送服务、公共模板业务包、跨模块凭证、通用消息测试记录或共同渠道注册表。

邮件与短信分别定义自己的模板引擎接口和注册表，各自当前版本只交付 Go 引擎。两者可以调用 Go 标准库，但不共用参数校验、模板 CRUD、渲染服务、版本或默认配置。钉钉当前范围不引入模板引擎。

独立性针对业务边界：继续使用现有单实例、同一 MySQL 安装和平台基础设施，包括会话/管理员授权、cryptox、受控网络访问、审计存储、基础文件 IO、HTTP 错误及 UI 基础组件。三模块使用独立的密钥用途、ETag 命名空间和审计动作前缀；不得借平台复用重新引入统一消息模型。不要求三个进程或三个数据库。

| 模块 | 后端/前端目录 | API 根路径 | 业务表 |
| --- | --- | --- | --- |
| 邮件 | `internal/modules/email`、`web/src/features/email` | `/api/v1/admin/email` | email_profile、email_sender_name、email_template、email_send_log |
| 短信 | `internal/modules/sms`、`web/src/features/sms` | `/api/v1/admin/sms` | sms_profile、sms_template、sms_send_log |
| 钉钉 | `internal/modules/dingtalk`、`web/src/features/dingtalk` | `/api/v1/admin/dingtalk` | dingtalk_robot |

八张表分别由邮件、短信、钉钉拥有。没有跨模块外键、逻辑业务引用、集合版本、业务事务或共享诊断资源。邮件模板可选择本模块 SMTP；短信模板只引用本模块供应商配置；钉钉 Token 只属于机器人配置。EmailProfile/SmsProfile 表示各自的一套发送配置；统一命名语义不意味着共享实现。邮件不建附件表。

## 2. 已确认功能范围

- 仅系统管理员维护、预览和测试；同类可建多份配置，每份一套认证材料。不提供项目、团队、个人归属或多凭证首选/兜底。
- SMTP 支持 TLS 直连及 STARTTLS、用户名和密码/授权码；发件地址与登录账号分开，多个发件名称且恰好一个默认项。
- 邮件支持纯文本、HTML、独立邮件模板和发送时附件。模板源码编辑、样例数据、隔离预览；模板不保存固定附件。附件随发送请求上传，结束清理，不保存独立元数据或附件 ID。
- 阿里云仅中国大陆短信；模板保存签名、远端模板 ID、抽象参数与供应商参数映射，每次测试一个手机号。本地短信模板可模拟生成待发正文。
- 钉钉输入 access token、secret、关键词，不输入完整 URL；服务端固定拼接官方地址，支持文本与 Markdown，不做 @ 提醒。
- 邮件与短信各自支持模板引擎扩展，当前版本各注册 Go，引擎标识及语法版本随模板保存。邮件主题/纯文本、短信正文用 text/template，邮件 HTML 用 html/template。阿里云远端映射不经过本地正文引擎。
- 邮件、短信分别保存真实发送日志 30 天，支持分页筛选；最近真实发送摘要由各自日志派生，不重复存储。草稿预览不写日志，短信本地模拟仍只保留最近模拟摘要；钉钉继续仅保留最近测试摘要。日志/摘要/审计不保存完整目标、正文、参数值或附件。

当前范围不建设业务类型、业务路由、触发规则、订阅、站内信、工作流、群发任务、定时发送、后台投递队列、自动重试、自动切换供应商、送达回执、验证码业务或账号邮箱功能。未来业务通过独立使用配置关联具体模块的资源，本次不设计该层，也不让业务调用方固定依赖供应商材料。

账号没有邮箱身份或邮件找回；SMTP 属于邮件模块，不改变账号模型。

## 3. 各模块分别遵循的操作约定

下列是对三个模块相同的产品要求，不是共享服务、共享状态机代码或共享数据表的授权。各模块自行实现并验证。

1. 配置结构合法且材料完整即可保存，不要求先通过外部验证。只有已保存且启用的资源可实际发送；页面未保存改动先保存或放弃。草稿渲染预览不外发。
2. 认证材料加密保存，普通编辑与完整认证替换分开；没有秘密读取、复制或导出接口。秘密不进入浏览器持久化存储、日志、审计或错误原文。
3. 停用保留数据，阻止新的真实发送。被短信模板引用的短信渠道先清除模板再删除；邮件独立模板不阻止 SMTP 删除。发送期间阻止删除正在使用的本模块资源。
4. 点击测试会真实发送，短信明确提示可能计费；本地短信模拟只生成正文。无自动重试，UI 禁用重复点击，服务端分别实现并发/频率限制。
5. accepted 仅表示受理，不能表述为最终送达/已读；明确拒绝、提交前失败、未知结果、执行中和仅渲染分别展示。超时/中断无法确认的结果为 unknown，不据此补发。
6. 发送前短事务核对权限、状态、版本及关联，邮件/短信各自插入发送日志，钉钉保存开始摘要，并写开始审计；记录失败不外发，网络调用不持数据库锁。外发后变化不能丢弃结果，原发送状态保留，最近摘要按快照标记 outdated。停用不能撤回已提交消息。
7. 进程重启或结果落库失败留下的 in_progress 转为 unknown；不靠审计或诊断恢复发送。请求丢失先查最近摘要，再次发送是新的显式操作。不承诺 exactly-once。
8. 邮件/短信日志每次实际发送一行，保留 30 天；日志不含重放负载，不是队列。删除配置/模板保留日志，清理后最近摘要允许为空。钉钉和本地短信模拟仍只有最新摘要。各类操作审计使用自己的命名空间，记录日志/摘要不更新配置版本；test_id 保证结果回写对应执行。

摘要建议包含 test_id、模式、状态、阶段、受控 reason_code、起止时间、操作者、所用本模块配置版本、目标掩码及受控供应商 request_id。邮件可另记附件数量/总字节数。无完整接收地址、正文、参数、附件名或原始供应商错误。模板源码/虚构样例是模板配置，与真实测试输入的留存限制区分。

## 4. 平台协议与数据约定

三套 API 分别注册管理员路由，沿用 Cookie/CSRF、data 封装、error.details、字符串 ID、UTC 时间、强 ETag、no-store。没有普通用户目录，也没有 `/admin/messages/channels` 或统一跨类型发送接口。

对象编辑、认证替换、发送测试携带所属资源 If-Match；缺失 428、格式非法 422、过期 412。涉及模板的测试另带本模块 template.version。外发前授权/版本失败确定不发送；外发后状态变化按第 3 节处理，不返回暗示安全重试的通用版本错误。

三类主体表独立使用 BIGINT UNSIGNED；邮件发件名称使用随机 CHAR(32) ID。时间使用 UTC DATETIME(3)，表名采用单数 snake_case，无物理外键/CHECK。code 唯一性限定在各模块相关表，不设置跨模块全局序列、code 目录或唯一约束。查询显式选择非秘密列，类型化配置与结构版本由所属模块校验。

同一次管理操作不涉及跨消息模块事务。各模块采用“用户授权锁在前，再本模块父资源、子资源按 ID 排序”。DDL 见各详细文档与 schema.sql 阅读副本；实际执行统一初始迁移。

## 5. 验证边界

邮件、短信、钉钉可以独立实施、验证和交付。一类新增供应商、修改模板或调整测试规则，不应要求另外两类修改业务代码或数据。必须检查：同值 ID/code 互不串用，密钥用途/ETag 不能跨模块互换，API 不接受其他模块资源，数据删除不影响其他模块。

必要测试见各详细设计。实现阶段运行相关测试、前端构建、MySQL 8.0/8.4 生命周期验证，以及 CI 同系列 golangci-lint config verify/run。真实服务联调只使用明确的测试账号和目标，模拟协议通过不等于真实服务验收。

资源限额和 DTO 按各模块当前契约执行，供应商协议变化需单独验证。当前版本只交付配置及显式测试，不接业务触发。
