# 扩展与依赖边界

扩展以已经出现的用例为依据。模块职责及依赖方向见[架构](overview.md)，功能范围和注册能力以代码为准，不预建尚无使用者的插件协议。

## 端口与事务

领域服务通过用例需要的小范围端口访问存储、文件、网络和执行环境。SQL、驱动错误及数据库事务句柄留在适配器；接口不逐个镜像数据库方法。

跨模块原子写入由实际用例组织协作端口，共享同一事务。不能让模块服务相互调用并各自开启事务，也不建立依赖所有模块的全局仓储。

替换数据库、模型框架或执行环境必须验证原有并发、授权、恢复和数据语义。接口形状相同不证明行为兼容。

## 配置与业务实体

受控配置由代码注册名称、类型、校验及默认值。业务身份、关系、权限和生命周期使用所属领域模型，不放入万能 KV 或由客户端任意定义。

配置演进保留既有值的语义，通过明确迁移处理名称及结构变化。秘密由专用用途的存储与加密能力管理，不因设置了“敏感”标记而允许明文持久化。

## 独立执行核心

通用模型与智能体核心不依赖平台身份、HTTP、SQL 或具体业务流程。平台宿主负责授权、持久化和资源生命周期，适配器负责框架及外部协议。

模块独立不要求单独进程或数据库。引入服务拆分前需明确远程身份、取消、租约及跨存储恢复成本。
