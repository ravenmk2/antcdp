# 测试与验收

## 检查命令

在仓库根目录使用统一入口：

```sh
node scripts/dev.mjs check
node scripts/dev.mjs verified
node scripts/dev.mjs test-db
```

`check` 汇总前后端检查，成功记录绑定源码、相关资源、配置及工具链；`verified` 确认记录是否仍有效。源码及工具链未变时复用有效结果，记录不能代替实库测试或浏览器验收。文档、AGENTS.md 和根 README 不触发代码检查记录失效，代码目录内的运行时资源仍参与。

按影响范围也可执行：

```sh
node scripts/build-web.mjs
node scripts/check-web.mjs
node --test scripts/*.test.mjs
go test ./...
go vet ./...
golangci-lint config verify
golangci-lint run
```

涉及 Go 代码、依赖或后端检查配置时，使用与 [CI Go action](../../.github/actions/check-go/action.yml)一致的 golangci-lint 版本及仓库配置。支持 CGO 的环境按需要运行 `go test -race`；未运行不能标为通过。格式工具的调用以工程脚本为准，不额外扩展默认检查门槛。

## 测试方法

优先验证可观察行为、事务边界、并发竞争和失败恢复，不写只复制实现的断言。测试规模随影响范围确定；代码或问题未变化时不重复完整检查。核心执行机制的验证重点见[助手架构](../architecture/agent-runtime.md#核心验证)。

前端使用 Testing Library 的角色、名称与标签定位，通过 userEvent 操作。异步步骤等待目标界面的语义标志；不以固定延时、放宽断言或增大超时掩盖问题。静态资源可访问和只读模拟数据不能替代真实交互验收。

## MySQL 集成测试

`test-db` 使用已配置的开发连接创建独立、唯一命名的空测试库，运行集成测试后只删除本次创建的库。开发验收库与自动化测试库隔离；清理失败保留记录，核对处理后再重试。此入口当前不启用 race 检测。

直接运行实库测试需分别配置测试所要求的独立空库与环境变量，入口见 [MySQL 测试](../../internal/store/mysql)和 [dev.mjs](../../scripts/dev.mjs)。不得复用业务库或其他测试正在使用的库；变量缺失而跳过不算验证通过。凭据仅通过受控本地配置或 CI 注入，不进入日志或版本控制。

结构、约束和事务行为必须由真实 MySQL 验证，内存仓储不能替代。文档引用及 SQL 阅读副本通过审核维护，不加入 CI 或检查脚本；纯文档修改不要求执行代码检查。

## 发布验证与报告

开发镜像、Test 和 Release 独立执行各自检查并构建产物，只复用公共 action，不跨流程消费产物。每个结果必须对应本次源码与配置；开发镜像冒烟通过不等于完整测试通过。矩阵和触发条件以[工作流](../../.github/workflows)为准，发布流程见[部署文档](../operations/deployment.md#发布与交付)。

报告区分静态检查、单元测试、受控模拟、实库、真实外部服务和浏览器验收，说明跳过项及原因。模拟通过不能证明实际权限、送达、网络策略、供应商行为或生产容量。

真实服务验证使用获准账号、目标与临时资源；沙箱验证区分执行、文件、取消、实例、持久卷和网络能力。结束后核对本次进程、实例及卷，保留必要证据并清理明确属于本次的资源，不执行全局清理。备份恢复、生产负载及跨进程部署能力需要专项验证。
