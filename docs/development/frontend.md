# 前端工程规范

前端是嵌入 Go 二进制的 React SPA，从根路径加载，通过同源 `/api/v1` 使用服务。技术选择见[架构总览](../architecture/overview.md)，版本、编译器及脚本以 [package.json](../../web/package.json) 和锁文件为准。

## 代码组织

| 目录 | 职责 |
| --- | --- |
| `web/src/app/`、`areas/` | 公共装配、身份与路由。控制台和工作区的区域代码，个人设置归工作区 |
| `web/src/features/` | 可跨区域使用的业务能力 |
| `web/src/components/` | 基础组件与平台组合 |
| `web/src/api/`、`types/` | 同源请求、协议边界及 DTO 类型 |
| `web/src/domain/`、`hooks/`、`lib/` | 共享校验、纯规则、hooks 与通用辅助能力 |
| `web/src/styles/`、`web/public/` | 样式与静态资源 |

区域之间不相互导入，共享层不反向依赖区域。基础组件不请求业务 API 或推断权限；业务组件负责数据获取、权限、转换和状态机，通过显式参数接收作用域。业务名称相似不构成合并请求与授权的依据。

共享身份、查询缓存及按用户隔离的助手运行状态放在区域共同祖先，切换账号时销毁旧用户状态。路由变更同步维护注册、路径守卫、登录返回及相关测试，兼容要求按实际消费者明确处理。

## 请求、缓存与协议

[API 客户端](../../web/src/api/client.ts)统一处理请求、CSRF、响应和错误。服务端逐次鉴权；不能根据路由前缀、同名 ID 或界面可见性猜测权限。

查询 Key 包含用户或资源归属、ID、筛选和分页。上下文切换后取消旧请求并隔离缓存；迟到响应不能覆盖新对象。条件版本、幂等和不确定结果核实遵循[HTTP 约定](../api/conventions.md)，不自动重放结果未知的写操作。

助手的命令、持久事件、临时流及展示投影关系集中见[执行与通讯架构](../architecture/agent-runtime.md)。组件不能越过协议层自行拼接缺口或把本地状态认作后端事实。

## 内容与资源

业务 ID 使用字符串，边界输入与响应按 Schema 校验。服务端提供的目录、默认值和参数约束按契约使用；未知字段不得静默丢弃。秘密不进入 URL、浏览器持久存储或日志。

Markdown、SVG、文件及外部内容视为不可信输入，按渲染器允许范围处理；模板转义不能代替隔离。上传、绑定与回收分开管理，不以传输完成推定业务保存完成。

第三方组件、字体和其他资源保留来源与许可，构建产物保持根路径和同源要求。类型检查与 ESLint 所使用的编译器接口都需在依赖调整后验证。启动、构建和交互测试分别见[本机开发](getting-started.md)与[测试规范](testing.md)。
